## 任务
用户要求把阶段 A（结构化转写 + ModelManager 模型常驻预加载）代码直接编译成 EXE。

## 打包过程（3 次尝试）
1. **第一次失败**：`--noconfirm` 清空 dist 时被残留 python 进程锁住 `mod/fun-asr-nano`（WinError 32）。
   根因：之前 kill 的预览脚本（preview_gui.py，session briny-tidepool）只杀了父进程，
   两个子进程（pid 9956/11944，14:32:13 启动）仍活着占着模型目录。Stop-Process 后解决。
2. **第二次失败**：同样 exit code 1，dist 只写了 138 项（不完整），COLLECT 阶段中途失败。
   真正错误被 Tee-Object + PowerShell stderr 误判机制弄丢。教训：打包日志不要用 Tee，用 Out-File 直写。
3. **第三次成功**：去掉 `--noconfirm`（先手动删 dist），`--log-level INFO` + `Out-File` 直写日志。
   **退出码 0，完整产物：13482 文件、_internal 4.01GB、EXE 99.6MB**。

## 关键经验
- PyInstaller 失败时 dist 可能是**部分写入**（138 vs 13482 文件），必须检查文件数验证完整性
- `--noconfirm` 会先清空 dist，失败则全部丢失——改为手动确认无进程占用后删除更安全
- Tee-Object 会吞掉部分 stderr/缓冲打乱顺序，用 `2>&1 | Out-File` 保真
- 打包前必须检查无 python/EXE 进程占用 mod 目录（预览脚本 kill 父进程会留子进程）
