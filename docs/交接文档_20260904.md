## 四、关键技术点（接手必读）

### 1. ASR 引擎（src/asr_engine.py）
- `ASR_MODELS` 注册表：nano / sensevoice / paraformer 三模型配置（label/desc/gen_extra 等）
- `ASREngine.load_model()`：AutoModel 本地加载，**必须 `sys.path.insert(0, asr_dir)` + `os.chdir(asr_dir)`**（model.py 依赖 ctc.py/tools 相对导入）；省略 remote_code 由 funasr 1.4.5 内置实现自动发现
- `transcribe()` 返回 `TranscriptionResult`：`sentences`（start_ms/end_ms/speaker/text）+ `speakers`（编号→显示名）+ `to_text()`
- VAD_PRESETS 三档 → `max_end_silence_time`（800/1500/2500ms）
- 模型目录：`mod/fun-asr-nano`（2GB，LLM 架构，GPU 旗舰）、`mod/sensevoice`（~900MB）、`mod/paraformer`（~850MB），公共 `mod/fsmn-vad` + `mod/cam++` + `mod/ct-punc`
- 音频加载坑：特殊编码 mp3 需先 ffmpeg 转 16k wav（main.py `convert_to_wav_16k` 已处理）

### 2. ModelManager（src/model_manager.py）
- 模块级单例 `_default_manager`，`get_manager(model_root, asr_model, vad_level)`
- `configure()` 运行时切换参数（改配置 → reset → 下次转写用新参数）
- 转写持锁串行化（funasr 推理非线程安全）

### 3. 历史记录（src/store.py）
- `RecordStore(APP_DIR)` —— **传根目录，内部自动拼 records/**（注意别传 records 再拼一次造成双层嵌套，已修过一次）
- 记录目录：`records/<id>/` = audio.wav + transcript.json + summary.md + meta.json
- 索引 `records/index.json`；状态机 pending→transcribed→summarized
- `migrate_legacy` 扫旧 recordings/*.wav 迁移（幂等）

### 4. 播放（src/player.py + main.py 阶段 C）
- `AudioPlayer` 封装 QMediaPlayer/QAudioOutput；信号 positionChanged/durationChanged/stateChanged
- 转写区 `txt_transcript` 是 **QTextBrowser**（非 QPlainTextEdit）：HTML 渲染句子，时间戳是 `jump:<start_ms>` 链接，`anchorClicked` 跳转
- 播放高亮：300ms QTimer 轮询位置 → `_highlight_current_sentence`（QTextCursor 定位 + extraSelections 黄底整 block）
- PyQt6 的 `QTextEdit.ExtraSelection` 需无参构造后赋 `cursor`/`format` 属性（不支持构造传参）
- 播放源优先当前记录 audio.wav（与转写同源，时间戳精确对齐）

### 5. 打包（build_exe.spec）
- onedir 模式，23 个 collect_all 包 + torch 动态库 + hiddenimports（asr_engine/model_manager/player 需显式）
- **教训**：打包前必须**先删干净旧 dist/MeetingAssistant**（否则 COLLECT 阶段静默失败）；不用 --noconfirm（避免中途清空）；不加短 timeout（全程约 8 分钟，曾被 60s timeout 误杀）
- 打包命令示例：
  ```
  .\venv\Scripts\python.exe -m PyInstaller build_exe.spec --log-level INFO
  ```
  成功后从 `runtime\mod\` 复制 mod/、`runtime\bin\` 复制 bin/ 到 `dist\MeetingAssistant\`
- 阶段 F 需在 spec 加：`collect_all('PyQt6.QtMultimedia')` + Qt 多媒体插件

### 6. 环境
- Python 3.11.10 venv，torch 2.5.1+cu121（本地 wheel），funasr 1.4.5（editable 从 runtime/FunASR 源码装，说话人分离需源码版）
- 开发机无 GPU（CPU 推理：模型加载 ~60-84s，4:45 音频转写 ~135s）；目标机 RTX 3060 GPU 正常
- 目标机 GPU 需驱动 ≥530.41（CUDA 12.1 要求），用户已更新驱动验证通过

## 九、打包三大坑（2026-09-04 阶段F 实测，重要）

1. **torch 扩展陈旧锁**：被打断的打包会在 `C:\Users\<用户名>\AppData\Local\torch_extensions\torch_extensions\Cache\py311_cu121\cudaops_ailut\lock` 留 0 字节锁文件 → 下次打包 torch 死等锁**无限挂起**（实测 40 分钟无进展）。打包前先删该目录（`rm -rf cudaops_ailut`）。

## 十、播放闪退根因记录（2026-09-04 定位 · 2026-09-07 修复版打包，重要）

**现象**：点「播放」→ durationChanged 正常 → 进程无日志瞬间消失（Windows 事件日志：Qt6Core.dll，0xc0000409 fail-fast）。

**根因**：PyQt6 6.11 / Qt 6.11 下，**只要 Python 侧连接了 `QMediaPlayer.playbackStateChanged`**，且播放器已挂 QAudioOutput，`play()` 即触发 Qt6Core 内部崩溃。逐信号隔离实验证实：连接 positionChanged/durationChanged/errorOccurred 均无恙，唯独 playbackStateChanged 必崩（Auto/Queued 连接类型都崩、与 ffmpeg/windows 后端无关、与是否显式 setDevice 无关）。

**修复（27cebed）**：
- 不连接 playbackStateChanged；新增 `AudioPlayer.playback_state()` 轮询
- main.py 的 300ms 高亮定时器兼做状态轮询 `_on_play_tick`，防抖状态机：接近时长末尾的 stopped 或连续 5 拍(~1.5s) stopped 才算真正停止，避免加载期误复位 UI/清高亮
- QAudioOutput 显式 `setDevice(默认设备)` + 监听 `audioOutputsChanged` 热插拔重绑；无设备时 play() 拦截并提示（不崩）
- 顺带修正 PyQt6 6.11 scoped enum 误用：`int(enum)` 会 TypeError，改用枚举比较 / `.value`

**教训**：Qt 信号能连不代表能连——新版本 PyQt6/Qt 组合务必对每条要连的信号做最小复现验证。真机出声仍需在目标机复核。
