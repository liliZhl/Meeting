# Fun-ASR-Nano 重复幻觉抑制（2026-09-02）

## 问题
用户 GUI 实测转写出现"幺幺幺幺…"（200+ 次重复）、此前"包子包子…"等
**LLM 解码重复幻觉**。Fun-ASR-Nano 是 LLM 架构（Qwen3-0.6B 解码器），
遇口音/噪声/模糊段时解码器陷入重复 token 死循环直到 max_new_tokens(512) 上限。
与流式/接口无关，一次性转写同样出现。属模型质量问题。

## 解决方案（已实测有效）
FunASR `generate(**cfg)` 支持透传 `llm_kwargs` 到 HF generate：
- 调用链（已逐行读源码确认）：
  `AutoModel.generate(**cfg)` → `inference_with_vad(**cfg)`
  → `deep_update(self.kwargs, cfg)`（cfg 并入 kwargs）
  → `self.inference(speech_j, model=model, kwargs=kwargs, **cfg)`
  → model.py `inference(**kwargs)` → `inference_llm(**kwargs)`
  → `kwargs.get("llm_kwargs", {})` → `self.llm.generate(..., **llm_kwargs)`
- 抑制参数：`llm_kwargs={"repetition_penalty": 1.15, "no_repeat_ngram_size": 3}`
  - repetition_penalty：对已生成 token 降权
  - no_repeat_ngram_size=3：禁止 3-gram 重复
- 已固化到 `src/asr_engine.py` transcribe() 的 generate 调用（git ae1abdd）

## 验证
A/B 对照（35s 切片，含用户幻觉段 3:11-3:23，来自 9.1-1.m4a）：
- A 默认参数：出现"零二零二零二零二… 幺幺幺…"重复倾向 + 胡言乱语
- B 抑制参数：重复消失，识别更准确
  （"对，他是零二零二，然后那个大一点最近哥…VIP通道九三一六平台"）
- 完整链路（2 分钟音频 27 句）：模型加载 56s + 转写 57s，**连续重复≥5 片段数=0**
