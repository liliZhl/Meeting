# 说话人分离（多人支持）方案评估

> 日期：2026-09-07　范围：MeetingAssistant 会议纪要工具
> 目标：把当前"双说话人"识别能力评估扩展到多人，给决策依据与可选路线。

## 一、现状

| 项 | 值 |
|---|---|
| 语音引擎 | FunASR 1.4.5（离线，`disable_update=True`） |
| 本地模型 | `mod/fun-asr-nano`、`mod/sensevoice`、`mod/paraformer`（主识别）＋ `fsmn-vad`（VAD）＋ `cam++`（说话人嵌入）＋ `ct-punc` |
| 说话人标注方式 | `AutoModel(..., spk_model=cam++)` → funasr 内部对 VAD 分句做说话人判定，结果句子带 `spk`（0 起始，代码 +1 → 说话人1/N） |
| UI 承载 | `speakers: dict[int,str]` 无数量上限，改名/合并/着色渲染按编号即可（**UI 无需改动即可显示 N 人**） |
| 实测 | 13:42（专利通话.mp3，24句）→ 分 2 人；14:42（9.1-1.m4a，81句）→ 单人音频全归 1 人 |

**关键限制**：FunASR 在 `spk_model` 路径下通常按 **cosine 相似度 + 阈值做"二值切换"判定**（当前/下一个说话人是否同人），并非真正 N 人聚类 → 两人场景最稳，>2 人会互相归并/切换错标。

## 二、可选路线对比

| # | 路线 | 离线可行性 | 包体增量 | 工作量 | 多人效果 | 风险 |
|---|---|---|---|---|---|---|
| A | **维持现状（cam++ 二值）** | ✅ | 0 | 0 | ❌ >2 人不可靠 | 无 |
| B | **换 FunASR 官方多说话人 ASR 模型**（AliMeeting 远场会议类） | ⚠️ 需有网机器下载后拷入 mod/ | ~1–2GB | 中（下载/适配/回归） | ✅ 专为多人会议训练 | 模型需联网中转获取；能否被 funasr 1.4.5 加载需验证；远场/近场声学差异 |
| C | **后处理 N 人聚类（推荐先做 spike）**：保留现主 ASR＋cam++，改为取出**每句说话人 embedding**，自行 K 聚类成 N 人 | ✅ 完全离线 | 0（复用 cam++） | 中（引擎改造 + 聚类 + 回归） | ✅ 理论上 N 人（K 需估） | **关键未知：funasr 内部是否暴露分句 embedding**（需代码验证，失败则该路线不成立） |
| D | 专业 diarization 管线（EEND-tta / pyannote 等） | ❌ 内网难 | 大（≥1GB + 运行时依赖） | 大 | ✅✅ 最专业 | 包体/依赖/联网限制，列为远期 |

## 三、建议：路线 C 的 spike 验证计划（1 天）

1. **验证 embedding 可获取性**（半天，最关键）
   - 读 funasr 1.4.5 `spk_model` 处理源码，确认 cam++ 对每个 VAD 段输出的中间结果是否含 embedding 向量（`speaker_embedding` 之类字段）
   - 若含 → 在 `asr_engine._parse_result` 旁收集 `[(段起止, embedding)]`，用 numpy 手写余弦相似度矩阵
2. **N 人聚类（半天）**
   - 不引 sklearn 也可用：相似度矩阵 → 凝聚式聚类/阈值法，K 用"最大平均相似度拐点"或固定 1..4 试最优
   - 对 2 人/3 人测试音（现场录 3 人各说几句）验证准确率与切句边界
3. **接入与回归**
   - 聚类结果覆盖 `spk` 标签（说话人编号重排为 1..N）
   - UI 零改动（speakers dict 已支持任意 N）；渲染/改名/合并/导出回归
   - 失败则回退路线 B 或维持 A

## 四、给用户的关键决策

- **若实际会议以 1–2 人为主**（访谈、周会口播）→ 维持 A，零成本
- **若有真实 3 人+ 会议录音且频次不低** → 建议批 1 天做路线 C spike；成功后功能上线，失败再评估 B（需外网中转模型）
- 本方案**不动 UI 架构**：N 人能力一旦有了，界面/导出天然支持

## 五、需要你提供的验证素材（若做 C）

- 1 条 2 人对话音频（确认不回归）
- 1 条 ≥3 人（3 人轮流说话即可）音频（验证聚类上限与准确率）
- 注明各段说话人真值，便于量化正确率
